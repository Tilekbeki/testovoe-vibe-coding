# Polza Companies Test

Тестовое задание на позицию технического специалиста / вайбкодера.

Проект включает загрузку данных в PostgreSQL, страницу `/companies` на Next.js, анализ `review.csv` и черновик ответов для блока про LLM-стек.

## Быстрый запуск

```powershell
npm install
copy .env.example .env
docker compose up -d
npm run db:schema
npm run db:load
npm run db:load-review
npm run dev:3001
```

Страница:

```text
http://127.0.0.1:3001/companies
```

Если порт `3001` занят, значит dev-сервер уже запущен. Можно сразу открыть страницу в браузере.

## Задача 1. Выгрузка -> PostgreSQL

Что сделано:

- спроектирована схема PostgreSQL в `db/schema.sql`;
- добавлена таблица `companies`;
- добавлены индексы для поиска, фильтров и аналитических запросов;
- реализована дедупликация по `source_id` и естественному ключу `name + city + address + phone`;
- реализован idempotent upsert: повторный запуск не должен плодить записи;
- проблемные строки не ломают весь импорт, а записываются в `import_anomalies`;
- обязательные SQL-запросы лежат в `db/queries.sql`.

Команды:

```powershell
npm run db:schema
npm run db:load
```

`npm run db:schema` применяет схему БД.

`npm run db:load` читает `data/page_001.json` ... `data/page_020.json` и загружает компании в PostgreSQL.

После импорта в консоли выводится понятная сводка:

```text
Было прочитано записей из JSON: ...
Успешно добавлено или обновлено компаний: ...
Пропущено проблемных или дублирующихся строк: ...
Зафиксировано аномалий в import_anomalies: ...
```

SQL-запросы из задания:

- топ-5 категорий по числу компаний;
- средний рейтинг по городам среди компаний с 10+ отзывами;
- доля компаний с сайтом по категориям.

Файл:

```text
db/queries.sql
```

## Задача 2. Мини-фича `/companies`

Что сделано:

- фронтенд вынесен в отдельную папку `frontend`;
- добавлена страница `frontend/app/companies/page.tsx`;
- данные тянутся серверно из PostgreSQL;
- секреты не попадают на клиент;
- используется `.env.example`, реальный `.env` не должен попадать в репозиторий;
- SQL-значения передаются параметрами, без небезопасной конкатенации пользовательского ввода;
- сортировка сделана через whitelist допустимых SQL-фрагментов.

На странице есть:

- поиск по названию;
- фильтр по городу;
- фильтр по категории;
- фильтр “только с сайтом”;
- фильтр по минимальному числу отзывов;
- сортировка кликом по заголовкам таблицы, как в Excel;
- повторный клик по той же колонке меняет направление сортировки;
- состояние “ничего не найдено”;
- loading-state со спинером;
- error-state с кнопкой повторной загрузки.

Запуск:

```powershell
npm run dev:3001
```

Проверить:

```text
http://127.0.0.1:3001/companies
```

Что проверить руками:

- открыть страницу без фильтров;
- ввести поиск по названию;
- выбрать город;
- выбрать категорию;
- включить “Только с сайтом”;
- кликнуть по заголовкам таблицы `Компания`, `Категория`, `Город`, `Рейтинг`, `Отзывы`, `Сайт`, `Телефон`;
- проверить, что повторный клик меняет направление сортировки;
- задать минимальное число отзывов;
- нажать “Сбросить”.

## Задача 3. `review.csv` и аномалии

Что сделано:

- реализована загрузка `review.csv` в `scripts/load-review.mjs`;
- строки CSV сохраняются в staging-таблицу `review_import_rows`;
- найденные проблемы пишутся в `import_anomalies`;
- отдельный локальный анализатор лежит в `scripts/analyze-data.mjs`;
- отчёт по странностям описан в `ANOMALIES.md`.

Команды:

```powershell
npm run db:load-review
npm run data:analyze
```

`npm run data:analyze` не пишет в базу. Она только читает JSON и CSV, сравнивает их и печатает диагностическую сводку.

Краткий результат анализа:

- JSON: 1000 строк, 994 уникальных `id`;
- в JSON найдено 6 дублей `id`;
- `review.csv`: 205 строк, 202 уникальных `id`;
- в `review.csv` найдено 3 дубля `id`;
- только 6 строк CSV совпадают с исходной JSON-базой по `id`;
- 199 строк CSV имеют `id`, которых нет в JSON;
- найдено 58 пустых `site`;
- найдено 20 пустых `phone`;
- найден 1 `rating = N/A`;
- найден 1 рейтинг с запятой: `"4,5"`.

Главный вывод: `review.csv` похож не на обычное обновление той же базы, а на смешанную или перепутанную выгрузку.

## Задача 4. LLM-стек

Файл:

```text
TASK4_ANSWERS_DRAFT.md
task4_answers.docx
```

В задании прямо сказано написать этот блок своими словами и без ИИ. Поэтому `TASK4_ANSWERS_DRAFT.md` оставлен как черновик-структура: его нужно переписать под реальный опыт кандидата перед отправкой. Файл `task4_answers.docx` создан в Word-формате для отправки.

## Структура файлов

```text
frontend/app/companies/page.tsx       страница компаний
frontend/app/companies/loading.tsx    спинер и skeleton во время загрузки
frontend/app/companies/error.tsx      fallback при ошибке роута
frontend/src/db/companies.ts          серверные запросы к PostgreSQL
db/schema.sql                схема БД
db/queries.sql               SQL-запросы из задания
scripts/load-companies.mjs   импорт JSON
scripts/load-review.mjs      импорт review.csv
scripts/analyze-data.mjs     анализ аномалий без записи в БД
scripts/create-task4-docx.mjs генерация task4_answers.docx
scripts/run-next.mjs         запуск Next.js из папки frontend с переменными из .env
ANOMALIES.md                 отчёт по странностям
TASK4_ANSWERS_DRAFT.md       черновик для задачи 4
task4_answers.docx           файл с ответами задачи 4 в Word-формате
```
